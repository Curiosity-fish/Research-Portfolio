# TFA 多租户科研 Agent 平台 — 详细需求文档

> 状态：需求已确认 v0.2
> 日期：2026-08-24
> 关联：`docs/ideas/tfa-multi-tenant-platform.md`（一页纸，方向 A）
> 代码库：`tech-finance-agent`（TFA / pi 框架改造版）

## 1. 目标

把现有 TFA harness 改造成**多用户 Web 平台**，部署在单台中等配置服务器（带 GPU），面向校内师生科研。

**1 个月后的可演示验收（demo 主线）**：
老师登录 → 创建课程组 → 添加学生 → 从 GitHub 安装技能、上传数据集并设为课程可见 → 学生在课程组下建项目 → 进入 VSCode 式项目工作台，加载课程技能、挂载数据集，聊天式跑科研 → 私有项目看不到课程库 → 用户发布外部智能体到智能体广场并查看在线状态 → 管理员可禁用账号、下架公开资源。

## 2. 角色与权限矩阵

| 操作 | 管理员 | 老师 | 学生 |
|---|---|---|---|
| 创建账号 | ✅ | ❌ | ❌ |
| 创建课程组 / 课题组 | ✅ | ✅ | ❌ |
| 邀请/添加成员进组 | ✅ | ✅（本组） | ❌ |
| 在组内共享技能/数据集 | ✅ | ✅（本组） | ✅（本组） |
| 创建私有项目 | ✅ | ✅ | ✅ |
| 在课程组下创建项目 | ✅ | ✅ | ✅（默认允许，见假设 A4） |
| 删除/禁用组、任免组长 | ✅ | ❌ | ❌ |
| 禁用账号、下架公开资源 | ✅ | ❌ | ❌ |

**权限链路（核心规则）**：
用户 → 项目（作用域）→ 可见库 = **自己的私有库** ∪（若项目挂课程组：**该组的库**）∪ **公开库**

## 3. 领域模型

```
User        { id, username, passwordHash, role: admin|teacher|student,
              status: active|disabled, createdAt }
CourseGroup { id, name, type: course|research, ownerId,
              members: [{ userId, role: owner|member }], status: active|archived, createdAt }
Project     { id, name, scope: { type: private } | { type: group, groupId },
              ownerId, sessionIds[], createdAt, updatedAt }
Skill       { id, name, repoUrl?, version, visibility: private|group|public,
              groupId?, ownerId, path, status: active|removed, createdAt }
Dataset     { id, name, sizeBytes, visibility: private|group|public,
              groupId?, ownerId, path, status: active|removed, createdAt }
Session     { id, projectId?, userId, containerId, status, cwd,
              permissionMode: request_approval|full_access,
              startedAt, endedAt }
AgentListing { id, name, description?, url, visibility: private|group|public,
              groupId?, ownerId, status: active|removed,
              availability: online|unavailable|unknown,
              lastCheckedAt?, createdAt, updatedAt }
```

- **一个课程/课题组可包含多个项目**；组内所有项目共享同一个课程库
- 可见性由 `visibility` + `groupId` 表达（私有=owner 独享；group=指定组可见；public=全员）
- 会话产出默认落在当前项目目录

## 4. 功能需求

### FR-1 认证与账号
- 管理员创建账号（老师/学生）、重置密码、禁用/启用
- 用户登录（用户名+密码），会话 token
- 登录后只看到自己有权限的项目与库

### FR-2 课程组 / 课题组
- 管理员/老师创建组（类型：课程/课题），添加/移除成员
- 老师可管理本组成员与组内共享资源；管理员可管全部组
- 删除组 = **归档**：保留组下项目与库；归档后不可加新成员、不可新建挂组项目；
  组库对现有成员仍可见（只读）
- 学生不创建组，只能被加入

### FR-3 项目
- 创建项目：私有 或 挂靠某课程组（需是组成员）
- 项目列表按组分组展示（扩展现有 `ProjectInfo`，见 6.3）
- 一个课程/课题组可包含多个项目；项目是文件、会话和研究产出的工作空间

### FR-4 技能库
- 从 GitHub 安装：填 URL → 平台 `git clone` 进对应库目录 → 入库可更新
- 自研/上传：平台内编辑 SKILL.md + 附属脚本，或上传目录
- 设置可见性：私有 / 课程组 / 公开；公开技能标记待审核
- 移除/下架（管理员可下架任何资源）

### FR-5 数据集库
- 上传科研数据集（大小上限见假设 A5），设置可见性，移除
- 会话中以只读方式提供给 agent

### FR-6 会话执行（核心闭环）
- 支持两类会话：通用会话（不绑定项目）和项目会话（绑定项目）
- 进入项目后默认打开三栏项目工作台：左侧文件树，中间文件内容区，右侧 Agent 对话区
- 中间区域支持文本/代码文件直接编辑和保存，并预览 PDF、图片、CSV 等常用科研文件
- Agent 可在当前项目工作空间内读取、修改和运行文件，结果回写项目目录
- 选项目 → 起 Docker 容器运行 TFA → 注入该项目可见的 skills 路径 + 数据集只读挂载
- 聊天式：流式输出、可交互（复用现有 shell Web 聊天能力）
- 会话权限支持：
  - `request_approval`（请求批准）：高风险操作执行前请求用户确认
  - `full_access`（完全访问）：在当前项目容器范围内自动执行，不突破项目、用户和服务器隔离
- 默认权限模式为 `request_approval`；用户可在项目会话中切换
- 会话持久化（现有 SQLite session-backend），产出落项目目录
- 容器资源限额、会话超时自动销毁、管理端可终止

### FR-7 管理端（最小可用）
- 用户管理：建号/禁用/重置
- 组管理：建组/加人/删组/任免组长
- 资源治理：公开资源审核标记、下架
- 会话监控最小版：会话列表 + 容器状态 + 终止按钮

### FR-8 系统配置
- 自部署模型接入（Ollama，见假设 A6）
- 默认模型设置；用户可自带 Key 覆盖（复用现有模型设置抽屉）

### FR-9 智能体广场
- 用户可以登记自己已经独立部署的智能体网页，至少填写名称、访问链接、简介和可见范围
- 智能体可见性支持：仅自己、课程/课题组、全平台公开
- 权限规则：
  - 创建者可以编辑、下线和删除自己的智能体
  - 课程/课题组管理员可以管理本组智能体
  - 平台管理员可以删除任何公开智能体
- 公开智能体可以直接发布，无需管理员事前审核；管理员保留事后删除权限
- 广场按用户权限展示智能体卡片；用户点击后在新标签页/新窗口打开外部网页
- 平台不托管、内嵌、代理运行或统一调用外部智能体，也不负责外部智能体的登录状态
- 平台定期检查登记链接的 HTTP 可访问性，并显示“在线”“暂时不可用”或“尚未检测”状态及最近检测时间
- 链接暂时不可用时仍保留广场卡片，不自动隐藏或删除；用户仍可点击链接尝试打开

## 5. 隔离与权限设计

- **三层可见性在存储层落地**（不只靠 UI 过滤）：
  - 用户私有库目录：仅本人
  - 课程库目录：按组授权
  - 公开库目录：全员
- **执行面**：每个活跃会话一个 Docker 容器（TFA 纯 Docker 模式）
  - 注入：本项目可见 skills 路径（settings.skills）、数据集只读挂载、Ollama 端点或用户 Key
  - 权限：`request_approval` 与 `full_access` 只控制当前容器内工具操作的批准策略；两者都不能访问宿主机或其他项目
  - 约束：cgroup CPU/内存限额、磁盘配额、会话超时、网络策略（可选）
- **控制面/执行面分离**：Web + 数据库 + ACL 在控制面；agent 只在容器里跑
- 未来升级微 VM 时仅替换执行后端，控制面不变
- **外部智能体边界**：智能体广场只保存外部网页目录信息和可用性状态，不将外部智能体纳入本平台执行隔离边界

## 6. 技术架构（基于现有代码）

- **控制面**：扩展 `packages/shell/src/server/http-server.ts`（REST + SSE + 静态托管）
  - 新增：认证中间件、用户/组/项目/资源 CRUD、可见性过滤
  - 数据库：SQLite（现有 `packages/session-backends/sqlite-node` 可扩展或新增表）
- **前端**：Vue3 `packages/shell/web` 扩展：项目/组/库管理页、管理端页
  - 现有 `ProjectInfo`（`web/src/api/types.ts`）增加 `scope` 字段
- **执行面**：Docker 容器跑 `packages/coding-agent`（tfa CLI），通过现有 RPC/SSE 通信流式输出
- **技能加载**：复用 TFA 技能机制（`~/.tfa/agent/skills/`、settings `skills` 数组、`/skill:name`），按项目注入对应目录实现作用域隔离
- **模型**：Ollama（OpenAI 兼容端点或 `packages/ai` 的 llama-cpp 支持）或 BYOK

## 7. 非功能需求

- 安全：密码哈希、会话 token、容器资源隔离、密钥不落共享磁盘（BYOK 仅注入本人容器）
- 性能：单机 ≤100 用户、低并发（~10 个活跃会话）
- 可用性：单机部署（docker compose）；失败会话可终止重启；智能体广场链接健康检查失败时保留资源并显示不可用状态

## 8. 分期

**MVP（1 个月）**：FR-1 ~ FR-9；监控只做"会话列表 + 终止"；项目工作台先支持文本/代码编辑和常用科研文件预览，智能体广场先支持外部链接目录与健康状态
**二期**：监控仪表盘、用量统计、审核流自动化、学生建组（如需要）、微 VM、SSO、技能市场集成（SkillHub）

## 10. 验收标准（demo 脚本）

1. 管理员建号 → 老师登录
2. 老师创建课程组"金融数据分析" → 添加 2 名学生
3. 老师从 GitHub 安装 1 个技能 + 上传 1 份数据集 → 设为课程可见
4. 学生登录 → 在课程组下建项目 → 起会话 → 能看到课程库技能与数据集 → 聊天式跑通
5. 学生私有项目 → 看不到课程库
6. 非本组老师 → 看不到该组库
7. 公开技能 → 全员可见；管理员下架 → 立即消失
8. 会话容器资源受限；管理员可终止会话
9. 禁用某账号 → 该用户无法登录
10. 通用会话不绑定项目；项目会话进入三栏工作台，能够浏览文件、编辑并保存文本/代码、预览常用科研文件
11. 项目会话中 Agent 能读取、修改和运行当前项目文件；切换 `request_approval` 与 `full_access` 后策略生效，完全访问不能越过项目容器
12. 用户登记私有、课程/课题组和公开智能体；不同用户按可见性看到对应卡片，公开智能体无需事前审核即可发布
13. 智能体卡片点击后在新标签页打开；健康检查失败后仍保留卡片并显示“暂时不可用”，仍可点击尝试打开
