## 1. 项目概述

把现有 TFA harness（单用户本地 coding agent）改造成**多用户 Web 平台**：校内师生在自托管、多租户环境中，把 AI 技能与科研数据集组织成「私有 / 课程课题组 / 公开」三层库，由项目决定每个 agent 会话能访问哪些库，在沙箱中聊天式跑科研。控制面（Web + SQLite + ACL）与执行面（Docker 每会话）分离。

## 4. 关键技术决策

1. **A1（已验证）**：多租户执行器必须 `tfa --no-skills --skill <目录>`，禁用默认全局技能目录，否则跨会话泄漏。
2. **A6（已验证）**：Ollama 用自定义 provider + OpenAI 兼容 `/v1` 端点接入；DeepSeek 为内置 provider。
3. **可见性在存储层强制**：`skillListVisible`/`datasetListVisible`/`projectListVisible` 用 SQL 过滤，不靠 UI 过滤。
4. **归档组语义**：不可加人、不可新建挂组项目/组资源；组库与历史项目对现有成员**仍可见（只读）**（T5 决策调整）。
5. **目录按资源 id 平铺 + DB ACL 强制**（对 plan 决策 4 的细化），避免改可见性搬目录。
6. **错误码**：沿用 `TfaServerError` 既有码（重复/冲突→400）；新增 `QuotaExceededError`→413；无 conflict 码。
7. **桥接复用 `RpcClient`**（coding-agent 自带 spawn + JSONL），未重复造协议；会话默认仍 in-process，RPC 桥接为 opt-in（`createRpcSession`）。
