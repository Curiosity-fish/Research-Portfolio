# 人生规划智能体长期记忆：部署与验收

## 已实现的链路

```text
学生浏览器
  -> Spring Boot /api/agents/life-planning/chat（JWT + 仅学生角色）
  -> Mem0：检索本学生已确认的低敏记忆
  -> E-Agent Workflow API：生成规划答复
  -> 仅在学生勾选确认时写入 Mem0
```

浏览器不再直接持有“AI 人生规划”的 E-Agent 或 Mem0 密钥。Mem0 内的 `user_id` 由后端用 `MEM0_IDENTITY_SECRET` 对内部用户 ID 做 HMAC 派生，不能从中还原学号或用户 ID。

## 1. 部署 Mem0

将 `C:\Users\BenBen\Downloads\mem0-main.zip` 解压到校内受控服务器。在 Mem0 的 `server` 目录中，按其 `README.md` 配置 `.env` 后启动。生产环境必须：

1. 设置强随机的 `POSTGRES_PASSWORD`、`JWT_SECRET`，以及 Mem0 的 API key。
2. 将 Mem0 API 限制为仅 Spring Boot 服务网段可访问；不要开放给学生浏览器。
3. 设置 `MEM0_TELEMETRY=false`，并按学校制度配置请求日志的保留期限。
4. 为 Mem0 使用独立的 PostgreSQL/pgvector 数据卷，并配置备份与删除演练。

Mem0 API 的默认地址是 `http://<mem0-host>:8888`，可通过 `http://<mem0-host>:8888/docs` 验证接口与 API key。

本机演示环境可使用项目脚本启动。Docker Desktop 已运行且准备好 OpenAI API Key 后，在项目根目录执行：

```powershell
.\scripts\start-mem0-memory.ps1 `
  -OpenAiApiKey '<OpenAI API Key>' `
  -Mem0ApiKey '<至少 32 字节的随机 API Key>' `
  -IdentitySecret '<至少 32 字节的随机身份派生密钥>'
```

脚本会把 Mem0 解压到 `outputs/runtime/mem0/`，启动 API、PostgreSQL 和管理界面，并关闭匿名遥测。停止开发环境使用：

```powershell
.\scripts\stop-mem0-memory.ps1
```

## 2. 配置 Spring Boot

在部署环境的密钥管理系统或未提交的 `application-dev.yml` 中配置以下环境变量：

```text
MEM0_ENABLED=true
MEM0_BASE_URL=http://<mem0-host>:8888
MEM0_API_KEY=<Mem0 API key>
MEM0_IDENTITY_SECRET=<至少 32 字节的随机值>

EAGENT_BASE_URL=http://<e-agent-host>:3001
EAGENT_LIFE_PLANNING_WORKFLOW_ID=dddf018e4b26470f96b27bc5e622028a
EAGENT_API_KEY=<可选；E-Agent 强制鉴权时填写服务端 API key>
```

`EAGENT_LIFE_PLANNING_WORKFLOW_ID` 是“规划2”工作流 ID。后端调用 `/api/v2/workflow/invoke`，按学生账号维护工作流会话，并处理首次返回输入节点的两阶段协议。`EAGENT_API_KEY` 不是必填项；如果 E-Agent 服务端强制鉴权，则必须由管理员提供它，不能使用 DeepSeek API key 替代。

不要把以上任何值写入 `academic-navigation-demo`、提交到 Git，或通过浏览器 Network 请求发送。

## 3. 可写入与禁止写入的数据

前端只有当学生主动勾选“将本次明确的长期目标或偏好保存为记忆”时才请求写入。后端限制单条长度为 360 字符，并拒绝下列内容：

- GPA、成绩、排名、预警、考勤、体测、健康、心理相关内容。
- 学号、身份证、手机号、地址、密码、Token、验证码、银行卡等标识或凭据。
- 模型推测的性格、能力、风险标签。

允许保存的示例：职业/升学目标、地域意向、预算约束、明确确认的行动计划、沟通偏好。

## 4. 上线验收

1. 使用两个不同学生账号，分别保存不同的低敏职业目标；相互对话和“管理长期记忆”中均不得看到对方内容。
2. 学生勾选保存“GPA 是 3.8”后，Mem0 不得新增这条记忆。
3. 学生保存“毕业后优先在杭州从事教育科技工作”后，新建会话追问发展方向，答复应能合理利用该偏好。
4. 在“管理长期记忆”删除一条记忆后，再追问相关内容，后端不得再检索到该记忆。
5. 停止 Mem0 后，聊天仍可调用 E-Agent；仅跨会话个性化不可用。删除接口应返回服务不可用。
6. 未登录、教师、系主任、院领导访问 `/api/agents/life-planning/**` 时必须被拒绝。
7. 检查浏览器构建产物与 Network 面板，不得出现 `MEM0_API_KEY` 或 `EAGENT_API_KEY`。

## 5. 运行接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/agents/life-planning/chat` | 带当前问题、历史和确认写入标志的受控对话 |
| `GET` | `/api/agents/life-planning/memories` | 读取当前学生自己的低敏长期记忆 |
| `DELETE` | `/api/agents/life-planning/memories/{memoryId}` | 删除当前学生拥有的一条记忆 |

所有接口均要求学校 JWT，且 Controller 额外验证当前角色为 `student`。

后端仅将本轮所需的 GPA、排名、学分、非敏感画像与发展路径摘要提供给 E-Agent；预警、健康和心理维度不会进入该外部调用，也绝不会写入 Mem0。
