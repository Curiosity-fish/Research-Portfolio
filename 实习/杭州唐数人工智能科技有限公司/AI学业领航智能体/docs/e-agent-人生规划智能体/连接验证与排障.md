# 在 E-Agent 中验证本地数据库连接

## 1. 推荐验证方式：专用诊断接口

后端新增了只读诊断接口：

```text
GET http://127.0.0.1:18080/api/eagent/health
```

它不返回学生敏感信息，只返回：

```json
{
  "code": 200,
  "data": {
    "status": "connected",
    "database": "academic_nav",
    "databaseTime": "2026-08-14 10:30:00",
    "counts": {
      "students": 2560,
      "grades": 61440,
      "alerts": 3734
    }
  }
}
```

只要 `status=connected` 且关键表行数不为 0，就说明 E-Agent 已经通过隧道访问到本地 MySQL。

## 2. 在 E-Agent 中操作

1. 进入“构建 -> 工具 -> API 工具”。
2. 新建或导入一个 GET 工具：
   - 如果使用“从 URL 导入”，填 E-Agent 主机能访问的 OpenAPI：

```text
http://127.0.0.1:18080/api-docs
```

不要填 `http://localhost:8080/api-docs`，因为 E-Agent 的 URL 导入是在 E-Agent 后端执行的，后端无法访问你 Windows 的 `localhost`。

   - 如果 URL 下载失败，直接使用本目录的：

```text
config/check_local_database.openapi.json
```

把 JSON 内容粘贴到“OpenAPI Schema”输入框，不经过 URL 下载。

   - 工具名建议：`check_local_database`
3. 在“人生规划”工作流的 `agent` 节点中添加该工具。
4. 在测试对话中直接问：

```text
检查本地数据库连接
```

5. 如果模型调用了 `check_local_database`，并回复“已连接、学生数 2560”，说明验证通过。

## 3. 不用对话也能验证

在能访问 E-Agent 主机的终端里执行：

```bash
curl -s http://127.0.0.1:18080/api/eagent/health
```

或从本机先确认隧道状态：

```powershell
.\scripts\start-eagent-chain-tunnel.ps1 -Action Status
```

## 4. 如何判断失败

| 现象 | 判断 |
|---|---|
| 返回 `HTTP 401/403` | 接口未放行或 E-Agent 未带正确认证头 |
| 返回 `502` 或连接失败 | 本机 Spring Boot 未启动，或反向隧道未建立 |
| `status != connected` | 后端能访问，但数据库连接失败 |
| 表行数为 0 | 数据库连上了，但目标表为空或库名错误 |
| “Schema URL 下载失败” | URL 在 E-Agent 后端不可达，或填成了 `localhost:8080` | 先启动 `start-eagent-chain-tunnel.ps1`，再改用 `http://127.0.0.1:18080/api-docs`，或直接粘贴最小 OpenAPI JSON |

## 5. 快速排障顺序

1. 本机：

```powershell
curl.exe http://localhost:8080/api/eagent/health
```

2. node1：

```bash
curl -s http://127.0.0.1:18080/api/eagent/health
```

3. E-Agent 主机：

```bash
curl -s http://127.0.0.1:18080/api/eagent/health
```

三层都返回 200，说明本机数据库、后端、两段隧道和 E-Agent 链路都正常。

## 6. API 工具放不进节点的常见原因

在 E-Agent 中，API 工具不是画布节点，不能直接从左侧拖到画布里。正确做法是：

1. 先进入“构建 -> 工具”，创建并保存 API 工具。
2. 回到工作流画布。
3. 选中名称为“助手”的节点，不是“大模型”节点。
4. 在右侧配置面板找到“工具”分组。
5. 点击“+ 添加工具”。
6. 弹窗中切到“API工具”标签。
7. 搜索 `check_local_database` 并勾选。
8. 关闭弹窗并保存工作流。

如果还是放不进去，按下面检查：

| 现象 | 原因 | 处理 |
|---|---|---|
| 工具在“API工具”里搜索不到 | 工具没保存，或保存为 MCP/内置工具 | 回到“构建 -> 工具 -> API工具”重新创建并保存 |
| 只有“内置工具”和“MCP工具”，没有“API工具” | 当前工具列表未刷新 | 点击刷新，或重新进入页面 |
| 节点里根本没有“工具”分组 | 选错节点类型 | 使用“助手”节点，不是“大模型”节点 |
| 能勾选但关闭后不见了 | 没有点确认或工作流未保存 | 关闭弹窗前确认，最后保存工作流 |
| 工具参数里 URL 无法填写 | 创建工具时没有正确导入 schema | 使用 OpenAPI 手动填写 `path`、`method`，或导入本目录的 `academic-openapi.yaml` |

手动创建 `check_local_database` 的最小配置：

```text
名称：check_local_database
方法：GET
路径：/api/eagent/health
鉴权方式：无
Base URL：http://127.0.0.1:18080
```

如果 E-Agent 的 API 工具要求填写完整 URL，直接写：

```text
http://127.0.0.1:18080/api/eagent/health
```
