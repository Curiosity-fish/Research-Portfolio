## 四、后端开发规范（重要）

### 4.1 认证方式 — 必须接 CAS，禁止自建登录

```
Demo 现状：前端有独立登录页 + 角色选择，密码 123456
正式版要求：删除独立登录页，改为 CAS 统一认证跳转

CAS 对接流程：
1. 用户访问系统 → 未登录 → 重定向到学校 CAS 登录页
2. CAS 登录成功 → 携带 ticket 回调到系统
3. 后端用 ticket 向 CAS 验证，获取用户属性（工号/学号/角色）
4. 根据角色字段自动跳转：
   - 学生(student)      → /student/dashboard
   - 教师(teacher)      → /teacher/dashboard
   - 辅导员(counselor)  → /teacher/dashboard（与教师共用端）
   - 专业负责人(dept)   → /department/overview
   - 院领导(dean)       → /dean/dashboard

前端改造点：
- stores/auth.ts 中的 login() 函数改为接收 CAS 返回的 token
- 删除 views/login/Index.vue 中的账号密码表单
- router/index.ts 的 beforeEach 守卫改为验证 JWT token
```

### 4.2 数据库设计参考

**直接以 `src/types/index.ts` 为建表蓝图**，各接口对应数据库表：

| TypeScript 接口 | 对应数据表（建议） | 说明 |
|----------------|-----------------|------|
| `User` | `sys_user` | 用户基本信息，来自学籍/人事系统 |
| `Student` | `stu_info` | 学生档案，含GPA、排名 |
| `AlertItem` | `alert_record` | 预警记录主表，含 failedCourses（JSON字段）|
| `InterventionRecord` | `intervention_record` | 教师干预回填记录 |
| `AcademicProfile` | 聚合查询 | 由成绩、出勤、竞赛等多表聚合计算 |
| `HealthReport` | `health_report` | 体测数据，对接体测系统 |
| `ProfileDimension` | `profile_score` | 五维画像得分，定期批量计算写入 |
| `GpaTrendItem` | `gpa_history` | 各学期GPA历史，来自教务系统 |
| `JobItem` | `job_cache` | 招聘数据缓存表，外部爬取写入 |
| `GradSchool` | `school_cache` | 院校数据缓存表 |

**重要字段说明：**

```sql
-- alert_record 表关键字段
failed_courses  JSON      -- 挂科课程列表，如 ["高等数学","数据结构"]
level           ENUM      -- 'yellow','orange','red'
status          ENUM      -- 'pending','processing','resolved'
pushed_at       DATETIME  -- 推送时间，用于学生端/教师端同步判断

-- stu_info 表关键字段  
major_type      ENUM      -- 'normal'（师范）, 'non_normal'（非师范）⚠️ 发展引导分支的核心判断字段
```

### 4.3 API 接口规范

**统一格式：**

```json
{
  "code": 200,
  "message": "success",
  "data": { ... }
}
```

**核心接口清单（按优先级）：**

#### P0 — 登录与认证

```
POST /api/auth/cas-callback     # 接收CAS ticket，验证后返回JWT
POST /api/auth/logout           # 注销
GET  /api/auth/me               # 获取当前用户信息（含角色）
```

#### P0 — 预警相关（最核心）

```
GET  /api/alerts?level=&status=              # 预警列表（学生查本人，教师查全班）
GET  /api/alerts/:id                         # 预警详情（含 failedCourses）
POST /api/alerts/:id/confirm                 # 学生确认已查看
POST /api/alerts/:id/intervention            # 教师提交干预记录
GET  /api/alerts/unread-count                # 未读预警数（用于红点）

# ⚠️ 推送机制：后端检测到新预警时，通过 WebSocket 主动推送给在线的相关用户
# WebSocket 地址：ws://host/ws/alerts?token=xxx
```

#### P0 — 学生数据

```
GET  /api/student/dashboard                  # 首页KPI + GPA趋势
GET  /api/student/profile                    # 五维画像
GET  /api/student/profile/gpa-trend         # GPA历史趋势
GET  /api/student/health-reports             # 体测报告列表
GET  /api/student/health-reports/:id        # 体测报告详情
```

#### P1 — 教师/班级数据

```
GET  /api/teacher/dashboard                  # 班级驾驶舱数据
GET  /api/teacher/students                   # 班级学生列表
GET  /api/teacher/students/:studentId        # 单个学生画像（教师视角）
```

#### P1 — 发展引导

```
GET  /api/development/paths                  # 四路径匹配度分析
GET  /api/development/jobs?category=&page=  # 招聘岗位列表
GET  /api/development/schools?type=grad|overseas  # 院校列表
POST /api/development/analyze               # 提交目标，返回差距反推分析
```

#### P2 — 院系/院领导

```
GET  /api/department/overview               # 专业宏观数据
GET  /api/department/courses/heatmap        # 课程通过率热力图数据
GET  /api/department/plan-analysis?grade=  # 培养方案偏差（按年级）
GET  /api/dean/dashboard                    # 全院汇总数据
```

#### P2 — AI 智能体

```
GET  /api/agents                            # 智能体列表（含角色过滤）
POST /api/agents/:id/chat                   # 发起对话（流式响应 SSE）
GET  /api/agents/:id/history               # 对话历史
```

### 4.4 预警推送实现方案（重点）

```
推荐方案：WebSocket（Spring Boot + STOMP）

触发时机（后端定时任务或数据变更事件）：
  - 教务系统成绩同步后 → 计算是否触发挂科预警
  - 考勤系统数据同步后 → 计算出勤率是否低于阈值
  - 每日凌晨定时计算GPA → 是否跌破预警线

推送目标：
  - 学生端：推送给该学生本人
  - 教师端：推送给该学生的班级教师/辅导员
  - 管理端：红色预警时推送给专业负责人、院领导

前端接收（已预留位置，需实现）：
  stores/auth.ts 中在 login 成功后建立 WebSocket 连接
  各 Layout 组件中监听预警消息，更新红点计数
```

### 5.3 替换时的注意事项

| 注意点 | 说明 |
|-------|------|
| **字段名一致** | 后端返回的 JSON 字段名必须与 `types/index.ts` 中的接口字段名完全一致（驼峰），否则前端 TypeScript 报错 |
| **failedCourses 字段** | 后端存为 JSON 数组，返回时保持数组格式，前端预警卡片直接遍历渲染 |
| **ECharts 数据格式** | 图表数据格式固定（如热力图 `[[col, row, value]]`），后端返回时注意格式，不要随意改变 |
| **分页** | 招聘岗位、院校列表等大数据量接口需实现分页，前端已留有加载更多交互 |
| **CORS** | 开发阶段在 vite.config.ts 配置代理，生产用 Nginx 反向代理 |

**这是发展引导模块最核心的业务逻辑，必须正确实现：**

```
判断依据：学籍系统 → 专业属性 → major_type 字段

师范专业 → 发展引导显示：
  ① 教职路径（小学/中学/高校招聘，查教育局官网）
  ② 考研路径（教育学相关院校）
  ③ 出国路径（教育学硕士）

非师范专业 → 发展引导显示：
  ① 就业路径（BOSS直聘等社会招聘）
  ② 考研路径（对应专业院校）
  ③ 出国路径（对应专业海外院校）

Demo 中的 DevelopmentPath.vue 已实现路径切换UI，
后端只需在 /api/development/paths 接口根据学生 major_type 返回对应数据即可。
```

### 7.2 预警挂科课程详情

```
关键要求：预警不能只显示"挂科3门"，必须列出具体课程名称。

数据库设计：
  alert_record.failed_courses 存 JSON 数组：["高等数学（下）","线性代数","数据结构"]

前端展示（已实现）：
  - 学生端 Alerts.vue：挂科课程以红色/橙色 tag 展示在预警卡片中
  - 教师端 AlertManagement.vue：表格"预警内容"列下方展示课程 tag
  - 详情抽屉：el-descriptions 中有"挂科课程"一行

后端注意：返回 AlertItem 时，failedCourses 字段不能为 null，
挂科类预警必须有数据，非挂科预警传空数组 []
```

### 7.3 预警状态同步

```
业务要求：学生确认已查看、教师提交干预后，两端要同步。

实现方案：
  1. 学生点击"确认已查看" → POST /api/alerts/:id/confirm
  2. 后端更新 alert_record.student_confirmed_at
  3. 后端通过 WebSocket 推送消息给该预警关联的教师端
  4. 教师端预警列表中该条记录显示"学生已查看 HH:mm"

  反向同样：教师提交干预 → 推送给学生 → 学生预警详情页显示"班主任已联系"
```

### 7.4 培养方案偏差分析年级数据

```
Demo 中 PlanAnalysis.vue 内的 gradeDataMap 是写死的静态数据：
  2023级（大四）：standard=[48,62,20,18,12], actual=[46,58,28,14,12]
  2024级（大三）：standard=[40,44,12,10,10], actual=[39,41,18, 8, 9]
  2025级（大二）：standard=[30,22, 4, 4, 6], actual=[29,20, 8, 3, 5]
  2026级（大一）：standard=[18, 8, 0, 2, 2], actual=[17, 6, 2, 2, 2]

5个维度顺序固定：['公共基础','专业必修','专业选修','实践环节','通识教育']

后端需要提供接口：GET /api/department/plan-analysis?grade=2023
返回该年级的 standard[]、actual[]、tips[]（每个维度的建议文字）
```

## 八、开发环境配置

### 8.1 前端环境变量

在项目根目录创建 `.env.development`：

```bash
VITE_API_BASE_URL=http://localhost:8080   # 后端地址
VITE_WS_URL=ws://localhost:8080/ws        # WebSocket 地址
VITE_CAS_SERVER=https://cas.zjnu.edu.cn  # CAS 服务器地址
```

### 8.2 Vite 代理配置（已预留位置）

修改 `vite.config.ts`：

```typescript
server: {
  proxy: {
    '/api': {
      target: 'http://localhost:8080',
      changeOrigin: true,
    },
    '/ws': {
      target: 'ws://localhost:8080',
      ws: true,
    }
  }
}
```

### 8.3 后端推荐配置

```yaml
# application.yml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/academic_nav?useUnicode=true&characterEncoding=utf8
  redis:
    host: localhost
    port: 6379

cas:
  server-url: https://cas.zjnu.edu.cn
  service-url: http://your-domain/api/auth/cas-callback

mybatis-plus:
  configuration:
    map-underscore-to-camel-case: true   # 下划线自动转驼峰，与前端 types 对应
```
