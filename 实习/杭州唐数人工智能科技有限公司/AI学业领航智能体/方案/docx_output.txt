一、数据工程与治理服务要求：
序号
项目
要求
1.1
数据源调研与现状评估
服务内容： 
对学校现有各业务系统开展全面数据资产调研，梳理数据字典、接口现状与数据质量基线，输出接入可行性评估。
技术要求：
（1）调研范围覆盖全校业务系统：教务管理系统、学工管理系统、一卡通系统、图书馆管理系统、在线教学平台、心理健康测评系统、体育测评系统、宿舍门禁系统等。
（2）每类系统需输出数据表清单、核心字段说明、数据量级、更新频率、现有接口形式。
（3）评估报告须包含数据完整率初测结果和同字段跨系统一致性比对。
1.2
多源异构数据采集与接口开发
服务内容：
针对各业务系统开发标准化数据采集接口，支持 API 对接、数据库直连、文件批量导入等多种接入方式。
技术要求：
（1）接口调用成功率≥99.5%；单次接口响应时间≤500ms。
（2）支持增量同步与全量兜底两种同步模式。
（3）所有接口须提供日志记录及失败重试机制，重试次数≥3 次，采用指数退避间隔策略。
1.3
数据仓库分层建设
服务内容：
按 ODS→DWD→DWS→ADS 四层架构建设学业数据仓库，实现数据从原始贴源到应用层的全链路加工。
技术要求：
（1）ODS（贴源层）：保留各源系统原始数据，不做业务逻辑转换；历史数据保留周期≥5 年；数据入库延迟≤2 小时。
（2）DWD（明细层）：统一学生主键；完成字段标准化；完成去重、异常值剔除处理。
（3）DWS（汇总层）：建设五维画像指标宽表；每维度字段数量≥8 个；每生每学期生成一条画像快照。
（4）ADS（应用层）：按前端模块需求建设不少于 12 张应用宽表，含学生首页仪表盘、预警事件表、课程通过率表、院级态势汇总表等。
（5）整体数仓调度成功率≥99%；支持任务失败告警。
1.4
ETL 流程开发与自动化调度
服务内容：
开发完整的数据抽取、转换、加载流程，并基于调度平台实现自动化运行。
技术要求：
（1）ETL 作业实现日常自动调度，执行策略为每日 1 次全量核对 + 准实时增量同步。
（2）调度平台支持 DAG 依赖管理、上下游任务阻塞与并行控制。
（3）单日全量调度任务须在每日 6:00 前完成，保障日间系统数据可用。
（4）ETL 作业执行日志保留≥90 天，支持按任务、时间维度查询追溯。
（5）提供数据血缘追踪能力，可追溯从源表字段到应用层指标的完整数据链路。
（6）异常数据须自动打标（标记原因：缺失 / 超范围 / 格式错误），不得静默丢失。
1.5
数据质量治理
服务内容：
建立持续化数据质量监控体系，覆盖完整性、一致性、准确性、时效性四个维度。
技术要求：
（1）学业核心字段完整率≥98%。
（2）跨系统相同语义字段一致率≥99%。
（3）建设数据质量监控大盘，每日自动生成质量报告，异常指标超阈值后触发多渠道告警。
（4）提供数据问题工单机制，支持一线运营人员提交数据异常反馈，问题处理 SLA≤2 个工作日。
（5）每学期至少开展 1 次全量数据比对审计，输出正式审计报告。
1.6
学业预警指标体系与规则引擎建设
服务内容：
建设可配置的多级预警规则引擎，支持规则的增删改查，无需代码发版即可调整阈值。
技术要求：
（1）预警分级：设置黄色（关注）、橙色（干预）、红色（紧急）三级预警。
（2）内置预警规则不少于 15 条，覆盖四大维度：
成绩类：单科不及格、学期 GPA 低于阈值、多科成绩下滑趋势
行为类：出勤率低于阈值、连续缺课次数、作业未交率超限
生活类：一卡通消费异常、图书馆到馆频率骤降
综合类：多维度同步异常、多因素叠加预警
（3）支持规则权重配置与组合规则。
（4）规则执行后自动生成预警事件，推送至教师端，并标注时间戳、触发事件描述。
（5）预警推送支持系统内消息 + 邮件通知两种渠道。
（6）每学期开展 1 次历史预警命中率复盘，提供预警准确率统计报告。
1.7
数据安全与隐私合规建设
服务内容：
依据《个人信息保护法》《数据安全法》及国家等级保护要求，建设符合合规标准的数据安全体系。
技术要求：
（1）系统须满足国家网络安全等级保护三级要求，验收前完成对应整改并提供测评承诺。
（2）学生个人敏感信息实施字段级加密存储，采用 AES-256 或同等强度加密算法。
（3）数据访问实现基于角色的权限控制：学生仅可查看本人数据，教师仅可查看所辖班级数据，院系领导仅可查看所辖院系数据。
（4）数据库及数据接口访问留存全量操作日志，日志保留期≥180 天。
1.8
数据运维与监控保障服务
服务内容：
提供系统上线后的数据平台日常运维、监控巡检及故障响应服务。
技术要求：
（1）服务期≥1 年（自验收通过之日起计算）。
（2）提供 7×24 小时系统监控，故障告警响应时间≤15 分钟，P1 级故障修复时间≤4 小时。
（3）每月出具正式运维报告，内容包含 ETL 执行情况、数据质量评分、接口健康状态。
（4）支持源系统接口变更适配：因源系统升级导致的接口变更，3 个工作日内完成适配调整。

2.1
系统总体架构设计与基础环境建设
服务内容：
完成系统技术架构设计，搭建前后端基础框架、服务器环境及中间件。 
技术要求：
（1）前端：采用 Vue 3 / React 18 及以上主流前端框架，支持组件化开发，响应式适配 1280×720 及以上分辨率。
（2）后端：采用 RESTful API 架构，支持接口版本管理（v1/v2），自动生成 Swagger/OpenAPI 接口文档。
（3）数据库：采用关系型数据库（MySQL 8.0+ / PostgreSQL 14+）搭配缓存层（Redis 7.0+）。
（4）部署：支持私有化部署至学校服务器，提供 Docker Compose / Kubernetes 容器化部署方案，配套一键部署脚本。
（5）系统可用性≥99.5%。
（6）并发能力：支持 500 人以上同时在线，选课、成绩发布等峰值场景下不低于 1000 并发。
（7）接口性能：普通 API 响应时间 P95≤500ms，P99≤1s（不含 AI 生成类接口）；页面首屏加载时间≤3 秒（1080p 普通宽带环境）。
2.2
学生端功能模块
服务内容：
开发面向学生用户的全量功能模块，覆盖学业查询、智能服务、发展引导等场景。
技术要求：
（1）学业总览首页
展示核心 KPI：当前 GPA、专业排名、已修学分、总学分、预警状态，数据实时读取（T+0）。提供 GPA 趋势折线图，展示近 5 个学期历史趋势，含年级均值参考线。预警状态区分 4 种等级，状态变化配套视觉动效提示；骨架屏停留时长不超过 2 秒。
（2）AI 智能体广场
按四大分类展示全部可用智能体，支持关键词实时搜索过滤。智能体卡片展示名称、描述、分类标签、使用次数、上线状态；已上线智能体跳转对话页，未上线智能体做状态限制。对话页采用左侧历史边栏 + 右侧对话区的标准布局。
（3）学业画像模块
提供五维雷达图，配套班级均值参考线，支持点击查看维度明细。提供 GPA 历史趋势图，配套 AI 画像解读功能，内容基于学生数据动态生成，禁止通用模板。
（4）学期体检报告
支持切换查看近 8 学期历史报告，提供五维综合加权评分，划分 3 个健康等级。每份报告包含评分趋势、维度变化、风险项、改进建议（≥3 条），支持 PDF 导出。
（5）预警通知模块
三色区分预警等级，红色预警配置醒目横幅与处置建议。未读预警显示红点角标，详情页展示触发事件、描述、推送时间、处置建议。
（6）发展路径引导模块
覆盖考研、留学、考公、就业四条路径，每条路径展示匹配度评分、差距分析、行动清单、里程碑时间轴。路径切换动效耗时≤200ms；考研路径集成 AI 择校助手入口。
（7）智学导库
覆盖视频、文档、习题集至少 3 种资源类型，支持按类型筛选、按匹配度、时间排序。单条资源展示标题、类型标签、知识点、推荐理由、匹配度；初始展示≥15 条，支持加载更多。
（8）学业沙盘推演
可调节学分、课程难度、自习时长、课外活动 4 项参数，输出 GPA 预测、排名变化、风险等级、匹配度变化。参数调节实时响应，刷新延迟≤300ms；支持保存 5 次推演记录横向对比；页面底部配置免责说明。
2.3
教师端功能模块
服务内容：
开发面向班主任、任课教师的功能模块，覆盖班级管理、预警干预、学生画像等场景。
技术要求：
（1）班级驾驶舱
展示班级核心 KPI，支持多班级切换；提供班级群像雷达图，可与年级均值对比。提供重点预警学生快速清单、近 7 天新增预警趋势图。
（2）预警管理与干预记录
支持按预警等级、处置状态双维度筛选；列表展示学生信息、预警详情、状态、操作入口。点击「干预」弹出侧边抽屉，展示预警摘要、AI 根因分析、干预回填表单；提交后自动更新状态与时间戳。支持批量选中、批量标记状态操作。
（3）学生个体画像详情
支持从预警列表一键跳转；展示学生基本信息、AI 综合画像描述。并排展示五维雷达图与 GPA 趋势图；提供全量历史预警记录。
2.4
专业负责人端功能模块
服务内容：
开发面向专业负责人的功能模块，覆盖专业态势分析、课程质量评估、培养方案优化等场景。
技术要求：
（1）专业态势总览
提供跨年级 GPA 趋势对比图、预警分布环形图、重点关注学生表格。
展示专业核心数据卡片，配套年同比变化标识。
课程达成度分析
采用 ECharts 热力图展示课程 × 年级通过率，配套 AI 课程健康度评分列表。
（3）培养方案分析
展示课程分布饼图、难度曲线图，识别难度陡增节点；支持同类院校数据对比。提供 AI 优化建议面板，每条建议配套数据依据。
2.5
院领导端功能模块
服务内容：
开发面向院领导的全局仪表盘，覆盖全院学业质量总览、多维度对比分析场景。
技术要求：
（1）核心 KPI 大字展示：全院学生总数、综合平均 GPA、活跃预警人数、干预闭环率。
（2）提供各专业健康度横向条形图、近 12 周预警趋势折线图、干预闭环率饼图。
（3）支持按学院、按年级两个维度切换视图。
2.6
统一认证与权限管理建设
服务内容：
建设系统统一身份认证与分级权限管理体系，保障数据访问安全。
技术要求：
（1）支持对接学校统一身份认证，实现单点登录。
（2）角色权限严格隔离，各角色仅可访问管辖范围内的数据。
（3）管理员后台支持角色授权、账号管理、权限变更全量审计日志。
（4）会话默认超时设置为 2 小时，无操作自动退出登录。

3.1
智能体平台基础建设
服务内容：
建设支撑全部智能体运行的基础设施，包含大模型接入、知识库框架、向量数据库、多智能体编排平台。 
技术要求：
（1）大模型接入：支持接入不少于 1 个经国家网信办备案的大语言模型，支持私有化部署或 API 调用两种接入模式。
（2）上下文能力：单次对话支持不少于 8000 tokens 的上下文窗口。
（3）并发能力：平台整体支持不少于 50 路并发智能体请求，单请求超时阈值设置为 30 秒。
（4）知识库框架：采用 RAG架构，向量化存储学业相关知识文档，检索相关性召回率≥85%。
（5）智能体编排：支持多步工具调用，支持调用学业数据 API 获取实时学生数据。
（6）数据安全：学生数据不得用于外部模型训练，Prompt 设计内置隐私保护系统指令。
（7）提供智能体管理后台，支持 Prompt 版本管理、调试、运行效果监控。
3.2
学生端智能体开发
服务内容：
开发面向学生用户的多场景智能体，覆盖学业分析、升学规划、就业指导等场景。
技术要求：
（1）AI 本周学业报告智能体：调用学业数据生成个性化周报，包含评分、亮点、注意事项、行动建议；生成总耗时≤10 秒，预设问题命中率≥90%。
（2）AI 画像解读智能体：基于五维画像生成深度解读、优劣势分析、发展建议；支持至少 5 轮多轮对话上下文记忆。
（3）AI 考研择校助手：基于学生情况推荐三梯队院校；内置≥50 所院校近 3 年招录数据，每年更新；回答标注数据年份。
（4）AI 留学规划助手：评估申请竞争力、推荐院校梯度、给出材料建议；覆盖至少 3 个主流专业方向，内置≥30 所海外院校项目信息。
（5）AI 岗位匹配分析智能体：分析学生画像与岗位的匹配度，输出评分、优劣势、提升路径；支持自定义岗位名称，内容动态生成。
（6）AI 学业顾问智能体：支持自然语言查询个人学业数据；内置≥200 条教务 FAQ；超权限查询明确提示无权限，不返回错误信息。
（7）AI 学业沙盘推演智能体：基于历史数据模型预测学业结果；经过≥3 届学生数据回测，GPA 预测误差≤0.2；输出预测逻辑说明。
3.3
教师端智能体开发
服务内容：
开发面向教师用户的智能体，覆盖班级诊断、预警分析、面谈辅助等工作场景。
技术要求：
（1）AI 班级诊断报告智能体：自动生成周度班级学业健康报告；区分新增预警与持续预警；生成时长≤15 秒。
（2）AI 预警根因分析智能体：基于学生 6 周行为数据输出根因推断与面谈建议；结构化输出结论 + 证据 + 注意事项；面谈建议分阶段设计，具备可操作性。
（3）AI 面谈提纲生成智能体：基于预警等级生成差异化谈话提纲；支持输入补充信息动态调整；包含「避免事项」提示模块。
（4）AI 批量预警回复智能体：批量生成差异化处置意见；支持导出 Excel/PDF；每条意见标注跟进时限。
3.4
专业负责人端智能体开发
服务内容：
开发面向专业负责人的智能体，覆盖课程健康诊断、培养方案优化场景。
技术要求：
（1）AI 课程健康度诊断智能体：生成课程健康评分与专业综合评分；识别系统性问题与偶发性问题；改进建议配套数据支撑。
（2）AI 培养方案优化建议智能体：对比行业标准输出优化方案；内置≥5 所同类院校培养方案摘要；建议分三大类别，每类不少于 1 条。
3.5
院领导端智能体开发
服务内容：
开发面向院领导的智能体，覆盖院情汇总、跨专业对比分析场景。
技术要求：
（1）AI 月度院情摘要智能体：生成结构化院情汇报报告；包含执行摘要、数据亮点、风险预警、建议行动；支持导出 Word 格式。
（2）AI 跨专业对比分析智能体：横向对比各专业核心指标；区分绝对低分与快速下滑两类问题；输出配套文字描述，适配无图表场景。
3.6
智能体运营与迭代服务
服务内容：
提供服务期内智能体的质量监控、优化迭代与新增支持服务。
